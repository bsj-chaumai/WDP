# 課題 → 提案 マップ（memo の整理版）

Sắp xếp lại nội dung memo theo thứ tự: **課題 → Nguyên nhân → Hướng 提案 → Lợi ích và cải thiện cụ thể.**

Nội dung dựa trên memo, chưa thêm phán đoán mới.
Những mục cần bổ sung được ghi riêng ở phần cuối.

> **Lưu ý về số hiệu 課題:** file này dùng thứ tự trong memo.
> Trong `80-teian-genjo-kadai-scratch.md` và `81-teian-vi.md` thì thứ tự khác:
> 課題2 ở đó là vấn đề thời gian（tương ứng 課題3 ở đây），
> còn 課題3 ở đó là vấn đề After（tương ứng 課題2 ở đây）.

---

# Khung tổng thể

> 今までの「空間を作って終わり」の方法では、
> 「**作った後にどう使うか**」という顧客の問題を解決できていない。

→ **どうやって改善できるか** — đây là câu hỏi bao trùm cả ba 課題 bên dưới.

# 課題 1 — サーベイ結果が、提案の言葉に変わらない

## Nguyên nhân

サーベイからはスコアが得られます。
しかし「**どの場所が**」「**なぜ**」「**何を変えるべきか**」はスコアには含まれていません。

設問の大半が5段階評価で構成され、自由記述がないため、
**回答者が感じた理由がデータとして残りません。**

結果として、スコアを読み解いて提案に落とし込む作業は、
**コンサルタントの経験に依存します。**
同じ結果を見ても、提案に活かせる方とそうでない方が出てしまう状態です。

## Hướng 提案

### ① 理由を聞く層（設問側）

- 満足度が低い回答に対してのみ、追加の設問を表示します
- **どの場所か・どんな点か・仕事にどう影響しているか**を取得します
- 自由記述も加え、**レイアウト上で場所を指定できる**ようにします

### ② 判断を支える層（結果側）

- 「**どこ・なぜ・誰に・どれくらい影響しているか**」を集約した分析画面を追加します
- 採用する内容を選び、**そのまま使える形で出力**できるようにします

## Lợi ích và cải thiện cụ thể

**提案に入れる根拠の説得力を向上させる。**

具体的には:

- スコアだけでなく「どこ・なぜ」が残るため、提案内容が具体化する
- 読み解きが属人的でなくなり、担当者による差が縮まる

# 課題 2 — 有料化が難しい

## Nguyên nhân — nguyên nhân gốc

**現在の仕組みでは、改修の前後で「何がどう変わったのか」を示せていません。**

実際に残るのは「**空間がきれいになった**」「**改修が終わった**」という体感のみです。

そのため、次の連鎖が起きています。

```
改修前後の効果が示せていない
（残るのは体感のみ）
  ↓
継続して使う理由（使用継続の条件）が生まれない
  ↓
有料化するための根拠と説得力が揃わない
```

## Nguyên nhân — biểu hiện cụ thể

上記の結果として、次の状態が現れています。

| | 現れている状態 |
|---|---|
| **1** | **移転後のサーベイ実施数が少ない** |
| **2** | 比較用の数値が弱い |
| **3** | サーベイの内容が（移転後の状況に）適用しなくなってしまう |

2と3のいずれも、**現在のサーベイ内容には十分な訴求力がなく、
企業側が「効果を比較するために測りたい」と思う状態になっていない**という点で
共通しています。

**根拠：**

> 6項目の内、**すべてが移転というタイミングだけでは向上させるのが難しい**

事業計画にも、体感だけが残る状態についての記載があります。

> オフィスではその先が**おざなり**になっています。
> **いいオフィスができてみんな喜んでいる。と一見は映るからです。**

## Hướng 提案

### ① クライアントごとにサーベイ内容をカスタムできるよう改修

現在のような共通サーベイのみの形から変更します。

**目的：** クライアントに合ったサーベイを設計できる状態にする

- **既存の設問から選ぶ**
- **end user が関心を持っている内容について、設問を追加できる**

回答後には、**不満を選んだ回答者のデータから、
現在の不満点を集約した部分**を用意します。

### ② 改修前に決めておく目標項目

**オフィス改修を行う前（Before段階）で主要な目標項目を選び、
改修後の比較のためにそのまま維持します。**

### ③ カスタムする際に注目が必要な点

| # | 内容 |
|---|---|
| 1 | **前回挙がった内容の確認** |
| 2 | **Beforeの時点で目標を設定する** |
| 3 | **移転後の運用に関する設問を加える** |
| 4 | **回答者へのフィードバック** |

## Lợi ích và cải thiện cụ thể

**オフィスを作った後の比較において、効果の比較がより可視化される。**

そして、**end user 側の「比較したい」という意識を向上させられる。**

その結果:

```
改修前後の効果が示せる状態になる
  → 比較したい意識の向上
  → 定期利用の継続率が向上
  → 有料化の根拠と説得力が揃う
```

**原因の連鎖と対応しています。**
課題2の原因は「効果が示せていない」ことにあるため、
改善の効果もその順序で現れます。

| 原因 | 対応する改善 |
|---|---|
| 効果が示せていない | Before段階での目標設定 ＋ カスタムによる測る内容の見直し |
| 継続する理由が生まれない | 前回内容の確認 ＋ 回答者へのフィードバック |
| 有料化の根拠がない | 目標に対する結果を示せる状態 |

# 課題 3 — 提案準備の時間枠（3〜4週間）に収まらない

## Nguyên nhân

提案までにかかる期間は **3〜4週間**。
この中に収まらない工程が2つ残っています。

| # | 工程 |
|---|---|
| ① | **お申込みと規約の確認** |
| ② | **結果の分析と提案への反映** |

**すでに解決している部分：**
サーベイ実施にかかる時間は、**共通ID（共通URL）の導入により解決済み**。
ただし上記2工程は残っています。

### 工程① お申込みと規約の確認 — 現状

ヴィス様からも、**お申込みや確認のステップをWDP上で完結したい**という
ご要望をいただいています。

**現在の状況：**

- **クライアント作成**部分の申込フローについて**調査中**
- **確認が必要な規約が何か**は未確認 → **ヴィス様に確認予定**

### 工程② 結果の分析と提案への反映 — 現状

現在は、サーベイ結果を取得した後、
**コンサルタントが内容を確認し、数値から文章へ変換して提案に落とし込んでいます。**

すべて**手作業**で行われているため、時間がかかっています。

## Hướng 提案

### 工程① お申込みと規約の確認

**WDP上でお申込みと規約確認を完結できるようにします。**
（調査結果と確認事項を踏まえて詳細を確定）

### 工程② 結果の分析と提案への反映

回答後に、**サーベイのデータを自動で集約します。**

集約する内容の例:

- **不満の回答比率が高い設問**
- **回答者からの意見（自由記述）**

これらを **クイックレポート** としてまとめ、
**コンサルタントが end user の状況を最短で把握できる**状態にします。

## Lợi ích và cải thiện cụ thể

*（memo に記載なし → 補足が必要。下記「補足が必要な項目」参照）*

# 補足が必要な項目

memo の内容を整理した結果、次の点が未記載または未確定です。

## A. 内容として足りていない部分

| # | 項目 | 内容 |
|---|---|---|
| A1 | **課題3の「改善できること」** | 課題1・課題2には記載があるが、課題3には未記載。「3〜4週間の枠に収まる」「提案準備の工数が減る」「早い段階から実施できる件数が増える」などを整理する必要があります |
| A2 | **効果の測り方** | 「説得力が向上する」「比較意識が向上する」をどう確認するか。回答率・実施件数・提案件数などの指標を決める必要があります |
| A3 | **開発の順序** | 7つの提案内容のうち、どれを先に行うか。課題3②のクイックレポートは他より軽い可能性があります |
| A4 | **誰が使う機能なのか** | 提案内容ごとに、コンサルタント／XP／総務／回答者のどれが使うのかを明記すると、必要性が伝わりやすくなります |

## B. 技術的に確定が必要な部分

| # | 項目 | 内容 |
|---|---|---|
| B1 | **カスタム時の集計ロジックへの影響** | 既存の設問（文言・選択肢・尺度）は変更せず、「どの設問を配信するか」と「何を追加するか」で対応する方針を明記する必要があります。設問自体を変更すると過去スコアとの比較が崩れます |
| B2 | **Afterでどこまでの比較が必要か** | 目標設問の比較のみか、項目スコアまでか、ワークデザインスコアまでか。配信する設問数が大きく変わります |
| B3 | **「共通ID」の呼び方** | memo では「共通ID」、事業計画では「URL形式」と記載。ヴィス様への説明時に用語を揃える必要があります |
| B4 | **クイックレポートの集約範囲** | 「不満比率の高い設問」「自由記述」以外に何を含めるか |

## C. ヴィス様への確認事項

| # | 項目 | 状態 |
|---|---|---|
| C1 | **確認が必要な規約の内容** | memo に記載済み（確認予定）|
| C2 | **クライアント作成部分の申込フロー** | 調査中 |
| C3 | **Afterで使われている比較の範囲** | 未確認（B2 と同じ）|
| C4 | **移転後に運用面でよくいただくご相談** | カスタム時に追加する設問内容の判断材料 |
| C5 | **XDが入る案件で特に確認したい項目** | カスタムの対象範囲に関わる |

## D. 他の取り組みとの関係

| # | 項目 | 内容 |
|---|---|---|
| D1 | **AIレポートとの境界** | 「判断を支える層」「クイックレポート」がヴィス様社内のAIレポートと重複しないか。役割分担を整理する必要があります |
| D2 | **XD（エクスペリエンスデザイン）への影響** | カスタムで設問を絞る場合、XDが働きかける項目（エンゲージメント・カルチャーなど）が測れなくなる可能性があります |

# 整理して見えたこと

memo の内容を課題ごとに並べると、次の構造になっています。

```
課題1（結果 → 提案）  → 理由を聞く層 ＋ 判断を支える層
課題2（効果 → 有料化）→ カスタム ＋ Before目標 ＋ 4つの観点
課題3（時間枠）        → 申込・規約の完結 ＋ クイックレポート
```

**共通している考え方：**

いずれも「**測った後に何が残るか**」を変える内容になっています。

- 課題1：理由が残る
- 課題2：比較したい理由が残る
- 課題3：手作業ではなく形になって残る

この点を提案全体の方針として最初に置くと、
3つの課題が別々の話に見えにくくなります。
