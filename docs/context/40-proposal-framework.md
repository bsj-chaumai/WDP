# 提案フレーム（背景 → 課題 → 方針 → 絞込 → 提案 → 効果）

作成方針: 今回の提案は **「既出の顧客要望 ＋ 有料化 ＋ survey（有料化に接続）」** を軸とする。

---

## 【背景】

- Vis は Work Design = **WD × XD**、2030年に **250億** を目指す。
  XD + WDP で **約25億** を見込む（FY2030 詳細 19.45億）。
- FY2026 は **検証（MVP）フェーズ**。XD + WDP で **0.7億**、WDP は **After / spot** 中心。
- WDP は既に **受注支援** としての価値を証明している
  （受注率 +22.9pt / +25.4pt、間接効果 約1.4〜1.46億、年間約100件・有料約2件）。

## 【課題】

1. **有料化がスケールしない** — 価値は実証済みだが継続課金の形になっていない
   （Q9①が有料化、Q3 の受注理由は「after サーベイ＋効果の数値化」）。
2. **After が回っていない** — Before 83 件に対し After 5 件（2025年度）。
   エンド顧客が最重要とするのは **Before→After**（Q4）。
3. **サーベイと提案が未接続** — 結果を提案に落とし込むのが難しく（Q1）、
   オフィス提案準備の **3〜4週間**に サーベイ提案→実施→提案書化 が収まらない（Q10）。
4. **サーベイが「単発・固定」寄り** — 定点・継続利用（＝有料の受け皿）になっていない。

## 【方針】

- 提案の主語を **「WDPに機能を足す」から「有料の効果検証を、最初から売れて、移転後まで回せるようにする」** に変える。
- bravesoft は待たずに**能動的に提案**し、**ETA（8月末目処）**を明示する。
- **提案用（単発・付加価値）** と **継続用（定点・有料）** を明確に分けて設計する。
- **AIレポートは本線から外す**（Vis 社内AIで進行中、2026/10 目処）。背景・スピード議論としてのみ扱う。

## 【絞込】

対象を次の3本に絞る。

1. **有料化の本線** — After / 効果検証を再現可能な形で売り、運用できるようにする
2. **定点サーベイ** — ユーザーが内容を選べる／定期実行 → 継続課金の受け皿
3. **既出の要望への回答** — 人員配置マップ、申込・規約の完結、クライアント別サーベイカスタム（Q8）

対象外: AIレポート開発、大規模な独立アプリ。

## 【提案】松竹梅

> ※ dev 調査（`30-dev-survey-brief.md`）の結果を反映して確定する。

| プラン | 想定スコープ | 狙い |
|---|---|---|
| **梅** | After 実施の障壁除去（Before データ再利用・After 作成の簡略化・提案書への出力） | まず After を回す |
| **竹（推奨）** | 梅 ＋ **定点サーベイ**（ユーザーが内容選択・定期実行）＋ 課金の受け皿（プラン/権限） | **有料化を仕組みにする** |
| **松** | 竹 ＋ Q8 の要望（人員配置マップ／申込・規約の WDP 内完結／クライアント別カスタム） | 提案付加価値と継続利用の両取り |

各プランに以下を明記する:
- 提案用 / 継続用 の区別
- 概算工数（S/M/L）
- 前提・依存関係

## 【効果】

- **有料継続率**の向上（現状 年間約100件中 有料約2件）
- **After 実施率**の改善（現状 5 / 83）
- **受注率**の維持・向上（実績 +22.9pt / +25.4pt）
- **提案準備工数**の削減（3〜4週間の枠内に収める）

> KPI は Vis と合意して確定する（例: After 実施率、有料契約件数、効果検証の単価・パッケージ）。

## 【進め方】

1. 提案資料ドラフト作成（先行着手）
2. POC を動く状態にする
3. dev 調査（約1週間）→ 結果を提案に反映
4. 資料は小分けで送りフィードバックを受ける
5. 水曜（12/13 目安）にレビュー会 → 後日サマリー送付
