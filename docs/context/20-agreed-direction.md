# 社内で合意した方向性（提案の進め方）

## 1. 問題認識

現状はやや**受け身・スロー**。Vis側の決定を待ってから提案する形になりがちで、
待っている間に**機会を逃すリスク**がある（例: AIレポート）。

## 2. 方向性（方向性）

- 相手の決定を待たない。**bravesoft から能動的に提案する。**
- **スピードと ETA（提出予定日）を明示**する。目安は **8月末を目処**。
  - JA表現例: 「8月末を目処にご提案をお出しします」

## 3. AIレポートの扱い

- AIレポートは **Work Design Platform とは別系統**。
- 打ち合わせでは主に**スピード・逸失機会の例示**として使用。
- **今回の提案の主内容ではない。**

## 4. 今回の提案が向かう先

| 優先 | 内容 |
|---|---|
| **① 有料化** | どのクライアントが課金できた／できなかったかを分析 → 改善案を提案 |
| **② 既出の要望への回答** | 人員配置マップ 等、先方が既に書いている項目に対する方針を提示 |
| **③ Survey** | 「定期的な内容」だけでなく、**ユーザーが自分で survey 内容を選べる／作れる（定点型）** → **有料化に接続** |
| **④ 進行中の case** | 顧客視点のストーリーとして書き起こす |

### 補足（分析との整合）

- 有料化の分析は、**After / 効果検証がなぜ売れない・回らないか**の分析とセットにする
  （Q3: 有料は「after サーベイ＋効果の数値化」で獲得、Q5: Before 83 / After 5）。
- Survey は 2 層に分けて考える:
  - **提案用**（1回、付加価値）
  - **継続用・定点**（ユーザーが内容を選ぶ）→ **こちらが有料化の接点**

## 追うべきポイント（チェックリスト）

### 有料化
- どのクライアントが課金できた／できなかったか
- できなかった理由は何か → 改善案・機能提案につなげる

### Survey
- 「定期的な内容」だけに閉じない
- ユーザーが**自分で内容を選ぶ／自由に設定**する（定点型）→ **有料化に接続**
- この観点を**先方にも明示してもらいたい**

### 顧客から既に出ている要望
- 先方が既に書いている項目（例: 人員配置マップ ほか）
- 少なくとも**提案の中で方針を提示**する

**→ 今回の提案は「既出の顧客要望 ＋ 有料化 ＋ survey（有料化に接続）」を軸に構成する。**
