本資料は、WDP本番環境への誤アップロード事象について、チーム内で共有・振り返りを行うための報告書です。
顧客向け報告書の内容をベースに、原因・影響確認・再発防止（UI色分け / Browser Extension / 運用）を整理しています。

1. 事象概要

自動テスト用スクリプト作成のため、検証メンバーが STG と PRO の2タブを並行して開き、両環境の値を比較していた。 タブが近接していたこと、および両環境の画面外見が酷似していたことから、環境を取り違え、本番環境（PRO）へデータを投稿してしまった。

当日、別件で検証チーム内のテスト内容報告を行っていた際に、本問題が発覚した。

確認結果

  • 稼働分析設定は計算方式 Meraki のため、uploadファイル形式差異により 新規データ更新はエラーで完了しなかった。
  • 現時点まで、プロダクトデータ本体への差異・影響は確認されていない。
  • 確実を期すため、S3上のヴィス東京向け現行適用データ（従業員情報・出社滞在情報）を取得し、再uploadを実施。
  • 以下の表示データにも差異・誤りは確認されず。
    • トップ_稼働分析の表示データ
    • 現状把握_稼働分析の表示データ
  • 唯一、TOP画面・稼働分析エリアの 「更新日」が当日日付に変更 されたことを確認。

3. 原因

現在、システムへの自動テスト導入に向け、検証工数削減のためのスクリプト作成を進めている。 その過程で、計算値・表示値の正確性を担保するため、STGとPROの値を照らし合わせる必要があり、検証メンバーが両環境のタブを並行して操作していた。

本番環境とSTG環境は画面外見が非常に似ており、ドメイン以外での判別が難しい状態であったことに加え、 2つのタブを近接して操作していたことから、検証メンバーが環境を取り違え、本番環境へデータを投稿してしまった。

補足（チーム内） DEV/QC振り返りでは、「PROD上の既存データでlocator確認を急いだ」「時間短縮のためにPRODへuploadした」 「Productionデータ保護を最優先にする意識が不足していた」点も共有されている。 本件は本番誤操作として 2回目 であり、運用・UI・個人意識の三層で対策が必要。

4. 再発防止策（人的ミスのRisk低減）

4.1 UIによる環境色分け（対応済み Evidence）

STG / DEV 環境のヘッダー色を変更し、本番環境と視覚的に明確に区別できるようにした。 環境判定フラグにより非本番のみ配色を適用し、本番UIには影響させない。

実ファイル（参考）: docs/incident-reports/evidence/env-header-green.png / docs/incident-reports/evidence/env-header-yellow.png

4.2 Browser Extension（メンバー端末への導入）

チームメンバーのローカル端末に Browser Extension を導入し、 Productionドメインへアクセス／操作していることを即座に警告表示する。

  • 目的：UI色分けと併用し、「今いる環境がPRODである」ことを個人端末側でも強制的に意識させる
  • 対象：検証・開発メンバー全員の作業ブラウザ
  • 期待効果：STG/PRO並行操作時の取り違えを、画面内＋ブラウザ側の二重警告で抑止

4.3 運用ルールの徹底

  • PRODでデータ変更し得る操作は事前承認必須
    upload / setting変更 / 再設定など、PRODデータを変え得る操作は、実施前にLeaderへ報告し、承認後のみ実行する。
  • 環境比較作業も承認プロセス対象
    STGとPROの値比較が必要な場合も、勝手にPRODへ書き込み操作を行わない。
  • STGへ定期的に比較用データを用意（Dev対応）
    TesterがPRODへ上がって比較しなくても検証できるよう、Dev側で定期的にSTGへデータを用意する運用を進める。
  • 教育・共通認識の継続
    「Productionデータ保護を最優先」をチーム共通ルールとして明文化し、定期的に周知する。

5. チーム内 Action Checklist

  • 1. UI環境色分け STG/DEVヘッダー色分けを適用済み。Evidence確認済み。本番配色は変更しない。
  • 2. Browser Extension導入 メンバー端末へPROD警告Extensionを作成・配布・インストールする。
  • 3. 事前承認ルール PROD変更系操作はLeader承認後のみ。チャット/チケットで証跡を残す。
  • 4. STGデータ整備 Devが定期取得/同期し、TesterのPROD比較依存を減らす。
  • 5. Ticket管理 進捗・判断は DEV_WDT-1151 で継続管理。

6. まとめ

今回はデータ本体への影響は確認されなかったものの、更新日変更が発生し、顧客信頼に関わるインシデントとなった。 再発防止として、UI色分け（対応済み）、Browser ExtensionによるPROD警告、 事前承認運用、STGデータ整備を並行して実施する。
